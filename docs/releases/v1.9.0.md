# iPaper 1.9.0 — 阅读活动热力图、Daily 资产状态与 UTC+8 时间

候选发布记录；Registry 摘要及最终门禁结果在发布验收后填写，不能视为已经部署。

## 用户可见变化

- **阅读活动热力图**：文献库主区新增可折叠的「阅读活动」，设置页的阅读记录复用同一组件。默认近 12 周（周为列、周一至周日为行），可展开为近一年；浅紫到柔和紫的色阶、零值近白，图例写明 0 / <15 / <30 / <60 / ≥60 分钟并给出累计、本周与阅读天数。悬停、键盘聚焦、触屏点按都能看到「日期 · 分钟 · 有记录的论文篇数」，点击日期可回看当天论文并跳回阅读入口。组件在窄屏内部横向滚动，不会让整页横向溢出。
- **每日归日与计时**：阅读时长按 **UTC+8** 归日，跨北京时间的午夜会拆到两天；计时沿用「正文已加载、页面可见且有焦点」的条件。每个 30 秒读时段带一个 tick 标识，重放不会重复计账；不再由前端分别写两套统计，服务端在一次请求里同时更新逐条事件与旧的按日汇总，两套数据不会分叉。历史只有总分钟数的日期显示分钟并注明「篇数未记录」，不猜测论文。
- **Daily 资产状态**：列表按真实资产状态显示——「PDF 已就绪」「PDF 获取中」「PDF 获取失败」「文件缺失，已重新获取」「仅元数据」。论文行与候选行的 arXiv 版本号（`2609.19915` 与 `2609.19915v1`）现在按同一身份匹配，记录说 ready 但文件不存在时会如实标记为「文件缺失」并按 owner 重新排队获取，不再显示「PDF 已就绪」。
- **缩略图恢复**：封面请求只读取既有资产，不隐式触发下载；没有封面时返回可识别的 pending 状态并禁用负缓存，ETag 对应真实文件版本，因此补回封面后无需整页重载即可出现。浏览器只做私有的短缓存，不再用 public 长缓存共享别人的封面；缓存键包含 owner，两个账号不会互相看到对方的图片。Daily 就绪/失败状态与真实文件保持一致。
- **北京时间**：Daily 的最近检查 / 最近成功更新 / 下次检查、任务与事件日志、处理与聊天时间、阅读活动日期都显示为 **UTC+8**，界面标注「北京时间（UTC+8）」。绝对时刻仍以 UTC（`Z`）存储与返回，排序与经过时间不受影响；历史天真时间按 UTC 解读后换算，不做整库平移。arXiv 公告批次改用 `America/New_York` 真实时区数据计算（含夏令时与周末顺延），不再手工推算或加固定偏移。

既有论文、阅读位置、译文、结构内容、分析、聊天、书签、元数据、关键词、主题与阅读历史全部保留。

## 组件

仅 Web 1.9.0 发布；Translation/Document Worker 复用已验证 1.2.0 摘要（未改动运行代码与依赖）。公开组件矩阵在远端核验后附上。

## 验证与回退

发布门禁覆盖完整 Docker 非集成测试、前端类型/单元/构建、四份 Python 依赖审计、源码与三个部署镜像的 Trivy 扫描及 CycloneDX SBOM。新增覆盖：UTC+8 日界/月末年末/夏令时与公告批次单元测试、阅读活动合并规则、读时段幂等与跨午夜拆分、缩略图 owner 隔离与 ETag、arXiv 版本号匹配与缺失文件修复。真实论文截图由带版本/提交/镜像侧车的脚本生成，截图前断言主题与计算样式，结束按显式偏好语义恢复账号设置。

升级前重新检查任务并创建停写备份；回退使用本次备份的回退脚本恢复 **Web 1.8.2** ＋ Workers 1.2.0，继续使用当前数据库，保留用户数据与新增产物（阅读事件行按新增列兼容读取）。数据库变更只有增量列与索引，旧版本可继续读写既有字段。

## 正式产品验收

真实账号的阅读活动（累计/本周/天数、日期详情与论文回看）、Daily 列表的真实资产状态与缺图恢复、北京时间显示与旧记录保留；原文/译文/结构阅读与阅读位置、三篇论文切换、390 移动端与实际 Web 重启后的恢复。使用短期受控维护会话，不修改用户密码、阅读位置或主题偏好。
