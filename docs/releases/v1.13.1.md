# iPaper 1.13.1 — 阅读笔记可靠性收尾（R1–R8）

已发布并固定摘要部署；正式复核结果在发布后补记，两个 Worker 未重建。

源码提交 `ac82ea1`，平台 `linux/amd64`。

## 为什么发补丁

1.13.0 的独立验收（`.devnotes/ipaper-1.13.0-review.md`）确认：慢保存会覆盖新输入、失败草稿在切换面板后丢失、冲突解决会覆盖未看过的新版本、四类内容有三条断路、撤销必然修订冲突、多行回答重复保存返回 503、来源不能真实回访，以及"子单元已缓存仅待发布"仍被时间额度拦住。本轮逐项修复，并把复现纳入常驻回归；**没有放宽任何修订校验**。

## R1 自动保存与编辑版本绑定

- 编辑器维护单调编辑版本与**串行保存泵**：同一时刻只有一个 PUT，每次编辑只记录"想要的文本"，响应返回后继续发送最新文本。
- 只有"服务器确认的版本 == 当前编辑版本"才显示「已保存」；否则保持「未保存的修改」并继续保存。慢响应、重复响应、切换论文/账号后的响应都不能改写新的编辑器（每请求带论文/账号纪元校验）。
- 防抖与失焦共用同一个泵，不会制造重复并发保存；首次加载、手动重试、插入摘录、保存回答、冲突解决与普通输入共用同一套版本规则。
- 修复了 1.13.0 里受控 textarea 的写入缺陷（输入值未回写本地状态），现在可以正常连续输入。

## R2 失败草稿的可靠生命周期

- 未提交文本保存在按 `owner + paper` 隔离的会话级草稿表：切换问答/批注/笔记、收起侧栏、切换原文/译文、组件卸载后仍能取回，重新挂载时自动恢复。
- 失败有「重试保存」与有界自动重试（3 次，3/8/20 秒）；文案与实现一致。重试前先 GET 对账：服务器已有相同文本 → 直接确认已保存；服务器修订已前进 → 转为冲突，不用旧草稿覆盖。
- 有未保存内容时关闭页面前有离开提醒；退出登录/账号变化清空该 owner 草稿；不写入无边界 localStorage、不落日志。
- 「已保存 / 未保存的修改 / 保存中 / 保存失败 / 有并发编辑待选择」状态真实反映当前编辑版本。

## R3 冲突解决绑定所见修订并保留双方

- 409 后立即重新拉取笔记，展示服务器版本与我的草稿，并在**笔记页签与批注面板**都提供「保留服务器版本 / 保留我的草稿」，不再是只有提示没有按钮。
- 解决请求必须携带用户所见的 `revision`：期间出现第三次写入时返回 409 `stale_decision`，把未被看过的当前内容保存为**新的冲突副本**；选择草稿时被替换的服务器版本同样另存副本。
- 冲突记录不再删除（已应用的标记为 `resolved:<choice>`），不存在"声称两边都保留却删掉唯一副本"。

## R4 四类内容逐一修通

- **版式译文**：来源校验改为读取该 document 自己的受控文件（`file_ref` + 所有权/路径/指纹），不再拿原文 PDF 哈希代替。
- **结构原文**：查询按 `documentId`（此前把 result id 当作 document id，保存成功但列表为空）；结果与文档的对应关系在服务端核验。
- **结构译文**：`translationRevision` 接受现有字符串身份并核验其确实是该块当前的译文修订；整数身份仍可读。锚点还会校验块存在、字段存在、范围不越界。
- 四类内容分别走真实界面创建 → 列表可见 → 正文标记 → 刷新恢复 → 点击回访；局部翻译结果中仍然有效的译文可以正常使用。

## R5 批注编辑、改色、删除与撤销闭环

- 删除成功后使用服务器返回的新修订更新撤销记录；失败不显示已删除，撤销失败保留重试入口；后端继续拒绝旧修订。
- 批注条目新增「编辑」：改文字与四色改色，保存/冲突/失败都有状态；修改后刷新与回访仍正确。
- 可撤销记录、详情、列表与正文标记同步更新。

## R6 依据稳定身份判重

- 「存入本篇笔记」以 `(owner, paper, session, message)` 记录判重，摘录以 `(owner, paper, annotation)` 判重，正文用不可见身份标记确认是否已插入；不再依赖正文子串。
- 多行、列表、公式回答重复保存返回 200 且只保留一份；相同文本不同来源不会互相误判；摘录在正文被删除后再插入会恢复正文但不新增来源记录。只复制已持久化回答，不重新问模型。

## R7 真实来源、版本与阅读顺序

- 回答来源保存完整对象（标签、sourceId、可解析到的页/块），笔记面板提供可点击**回访**；不再是"UUID 前八位"字符串。
- 摘录插入的来源文字包含内容类型、页/块与（结构译文）修订。
- `_source_state` 比较文档哈希、结果修订与译文修订，并**逐字比较完整摘录**；重解析/重译/替换文件后不绘制旧位置，保留摘录并说明原因。
- 批注列表分页（默认 100，最大 200）并返回 `nextCursor`/`total`/`orderKey`，界面按文档内阅读顺序展示并「加载更多」，超过 200 条仍可访问与回访。
- 没有文字层时提供手写**页级记录**入口（页码 + 记录文字），不自动 OCR、不伪造精准选区。
- Markdown 导出含论文标识、内容类型、页/块与来源语义，剥离内部标记，不泄露主机路径或会话信息。
- 1.13.0 已产生的笔记、批注、摘录与冲突草稿兼容：旧记录继续可读，能可靠恢复的来源照常回访，不能恢复的如实标记为失效。

## R8 子单元已缓存时不再被时间额度拦住

- 执行器只在**确实有待发请求**时检查执行时间；块的全部子单元已缓存、只差发布结果时不再调用时间检查（每个真实请求仍经 `reserve_attempt` → `check` 受时间保护）。
- 续跑计划与执行同语义：识别整块已完成、子单元已齐未发布、部分单元缺失、仍需解析四种状态；复用检查点不重复调用、不清零累计用量；确有待发请求且时间耗尽时仍拒绝并要求增额。
- 保留 1.12.1 的部署上限、重译估算、逐维度实际用量、用户主动选择的 429 余量与其它任务类型边界。

## 回归与测试

- 后端 `tests/test_paper_notes.py` 扩到 15 项（版式译文自身文件、结构锚点与修订核验、冲突绑定所见修订与双方保留、多行回答幂等、撤销使用新修订、编辑改色、分页与阅读顺序、页级记录、失效版本降级等）；`tests/test_translation_budget.py` 扩到 33 项（缓存子单元发布 + 仍有请求时的时间保护）。
- 浏览器 `frontend/unified-tests/notes.spec.ts` 扩到 9 项（慢响应不覆盖新输入、失败草稿跨面板恢复与重试、冲突即时控件与双方保留、撤销用新修订、编辑改色持久、结构原文保存后立即可见，以及原有的持久高亮/笔记/回答三条）。套件串行执行并使用一次登录（隔离服务器对登录有限速）。
- 独立验收的 6 项后端复现中，5 项（含额度边界）现已通过；`test_undo_using_revision_kept_by_current_ui` **保留为失败诊断**（它模拟旧 UI 发送旧修订，正确后端仍应拒绝），常驻测试改为断言"旧修订 409、删除返回的新修订可撤销成功"。

## 限制与回退

- 仍不做全库笔记工作区、双链、知识图谱、跨论文检索、自动生成笔记与带批注 PDF 导出。
- 结构高亮以存下的范围与完整摘录校验为准，无法匹配时只显示块级来源与说明。
- 回退基线 **Web 1.13.0 ＋ Workers 1.2.0**；新增表可空、旧版本忽略，回退只切镜像，不用旧数据库覆盖用户新增的笔记与冲突草稿。回退会重新暴露 1.13.0 的笔记可靠性缺陷（慢保存覆盖、草稿丢失、冲突覆盖、批注断路），数据仍保留。
