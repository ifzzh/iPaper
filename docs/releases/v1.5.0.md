# iPaper 1.5.0：论文元数据与入库识别

安全入库完成后即可阅读，公开书目补全在后台执行；联网失败不会移动文件或阻止阅读。详情支持完整作者、机构、发表信息、标识符和来源链接的修订编辑，以及对应当前信息的 BibTeX 复制和下载。人工修改与主动清空受保护，过期保存返回冲突并保留草稿。

单篇和跨页批量补全共用持久任务；取消停止后续请求，重启恢复未完成的只读查询。每篇最多八次书目请求，有全局限流和缓存。重复提示区分文件相同、同篇及相关版本，不自动删除或合并。元数据补全不调用模型、MinerU 或 OCR，不生成标签或主题分类。

旧标题编辑不再暗中搜索并覆盖其他信息，旧刷新端点不再重命名文件或移动资产。上传、URL、Daily 入库和导入保存使用同一事务保护；Daily 未入库发现记录不进入首次回填。作者摘要仍是论文元数据，既有 AI 概览、解读、双翻译、聊天、书签和阅读位置保持原有绑定。

## 证据与来源限制

本次建立 30 个有固定判断依据的合成身份样本，覆盖同名、参考文献 DOI、作者顺序、团体/中文作者、arXiv 版本、OpenReview 匿名/投稿和无文本等情况；这些是隔离测试，不是 30 篇真实论文的在线验收。使用已有许可明确的 PDF 样例验证 Worker 入库。

真实新客户端已核对 Crossref `10.1038/nature14539` 的标题、作者、期刊、年份、卷期页码，复读命中缓存、零新增请求。首次单独来源预检的 arXiv 超时/429；正式回填退避后已取得精确版本的成功记录，仍有间歇性失败。DBLP 返回 HTML 验证页、OpenReview 返回 403，二者本轮没有真实书目通过证据；客户端如实拒绝异常内容，不绕过访问限制。用户可编辑可靠标识符、核对候选并重试；不得承诺所有论文都能自动补齐。详见[来源约束](../development/metadata.md)。

实际 Web 1.4.0 镜像完成隔离往返：旧 schema → 新书目及人工清空 → 旧镜像修改/新增论文 → 再升级；新旧用户修改、主动清空及文件路径均保留。补全进程在请求检查点退出后重新启动，已完成项不重跑。Edge 实测了详情、BibTeX 下载、跨页批次和两个标签的编辑冲突，保存 1920/1440/390 浅深视图。下方为本次发布门禁、正式部署与存量回填实测。
