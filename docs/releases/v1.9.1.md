# iPaper 1.9.1 — 阅读活动热力图版式：对齐铺满、类 GitHub 贡献图

候选发布记录；Registry 摘要及最终门禁结果在发布验收后填写，不能视为已经部署。

## 用户可见变化

- **对齐与铺满**：设置页的「阅读活动」不再是直接铺在页面上的裸区块，而是与「个人资料」「修改密码」等相邻卡片同宽、同边框、同内边距的卡片；文献库中的可折叠区也与工具栏、列表对齐。图形宽度按内容列铺满，不再在一侧留下大片空白。
- **类 GitHub 贡献图**：默认展示**近一年**（53 列，一周一列、周一至周日为行），可一键切回近 12 周；月份标签对齐在列上方，左侧只标一/三/五，单元格 3px 间距、3px 圆角，空值格用极淡描边区分，图例移到右下角（"少 ▢▢▢▢▢ 多"并标注 0 / <15 / <30 / <60 / ≥60 分钟）。
- **自适应与移动端**：列宽 `minmax(10px, 1fr)` 随内容宽度伸缩并设上限（避免短范围把方块放大），短范围居中显示；≤640px 保留 10px 单元格并在组件内部横向滚动，整页不会横向溢出。
- 数据口径、交互（悬停/聚焦/点按详情、点击日期回看论文）、北京时间归日与每日论文数均不变。

## 组件

仅 Web 1.9.1 发布；Translation/Document Worker 复用已验证 1.2.0 摘要（未改动运行代码与依赖）。公开组件矩阵在远端核验后附上。

## 验证与回退

门禁覆盖完整 Docker 非集成测试、前端类型/单元/构建、四份 Python 依赖审计、源码与三个部署镜像的 Trivy 扫描及 CycloneDX SBOM。浏览器回归在统一套件中新增热力图检查：默认近一年（≥52 列）、单元格 ≥9px、图形宽度不超过卡片且不少于其 60%、整页无横向溢出，以及 390 宽度下组件内可横向滚动。真实截图在候选镜像与正式部署上分别采集（1440 浅/深、390、12 周与一年、日期详情），侧车记录版本/提交/镜像与主题。

升级前重新检查任务并创建停写备份；回退使用本次备份的回退脚本恢复 **Web 1.9.0** ＋ Workers 1.2.0，继续使用当前数据库。本次只有前端样式与组件结构变化，无数据库迁移。

## 正式产品验收

设置页与文献库的阅读活动在 1440/390、浅深主题、近一年与近 12 周下的对齐、铺满、图例与滚动行为；日期详情回看；其余既有功能（阅读、Daily、时间显示）沿用 1.9.0 的验收结论并复核无回归。使用短期受控维护会话，不修改用户密码、阅读位置与主题偏好。
