# iPaper 1.11.0 — Daily 可靠发现：真实封面、状态闭环与调度可解释

已发布并固定摘要部署。正式只读探针、真实资产修复与正式截图结果在发布后补记；两个 Worker 未重建。

源码提交 `e474399`，平台 `linux/amd64`。

## 为什么做这一轮

用户截图中的 Daily 卡片长期停在"生成中"，第一篇 `2609.19915`（*Amortizing Physics-Informed Neural Solvers via Graph Hypernetworks*）的 PDF 与封面都不存在。只读盘点确认：426 条候选 ready、50 条 failed、24 条 retry_wait，其中 **73 条错误是 `paper_not_found`，且这 73 条都能按"去版本号身份"在当前 Daily 论文中找到对应记录**——不是 arXiv 网络失败，而是资产执行入口没有做身份解析。

## A. 真实资产：身份 → 文件 → 队列 → 封面

- 新增 `ipaper/arxiv_identity.py`：统一、严格的 arXiv 身份解析（基础 ID + 显式版本），接受裸 ID、`vN`、旧式 `category/NNNNNNN`、`arXiv:` 前缀、`abs`/`pdf` URL 与 `.pdf` 后缀；无法识别的值直接拒绝而不是截断猜测。SQL 谓词锚定在基础 ID 上（含旧式斜杠形式），不会命中相邻编号论文。
- `PaperDAO.find_papers_by_identity` / `get_daily_paper_by_identity`：owner 隔离的身份查询；`get_paper_by_arxiv_id` 与 `paper_store.get_by_arxiv_id` 改为身份匹配，发现去重也不再漏掉带版本的同篇论文。
- 重写 `process_paper_asset`：解析身份 → **优先复用本地已验证 PDF**（Daily 记录自身文件、Daily 暂存路径、同 owner 同身份的其他行，例如已入库副本）→ 仅在缺 PDF 时走受控官方下载（保留 `pdf_http_429` 等稳定错误码、超时、大小上限）→ 用本地 PDF 交给既有 Document Worker 生成真实首图 → 原子提交。
- 状态解耦：候选行新增 `thumbnail_status` / `thumbnail_error_code` / `requested_stage`。**PDF 可读但封面失败时 PDF 仍然可读**，只标记封面失败；`artifact_status` 不再被封面问题掩盖。
- 重试语义：`retry` 入口支持 `stage`（`thumbnail` 只重生成封面、复用本地 PDF；`pdf` 重新获取），未指定时按缺失项推断；重复入队不会重置退避或尝试次数，ready 且文件齐全的行不会被无意义重复入队。
- 发现 upsert 刷新排序元数据时**保留**处于 ready/queued/downloading/validating/retry_wait 的资产生命周期字段，后台重新发现不会把进行中或已成功的资产改回 candidate。
- 批量修复：先出 owner/ID/版本/原因限定的 dry-run 清单，再以条件 UPDATE（`asset_job_id IS NULL`、仅 failed/retry_wait）把记录交回既有的单飞、限速协调器执行；没有有效论文行的孤立候选标记为 `paper_removed` 终态，不再无效重试。

## B. 状态自己更新，操作结果可靠

- 列表按论文解耦输出 `pdf_status` 与 `cover_status`（`ready` / `pending` / `generating` / `failed` / `missing` / `unavailable`），退避等待显示"等待重试：<北京时间>"。
- 有活动资产时列表按 6 秒**有界、可中止、仅可见**刷新，全部进入终态即停止；刷新保持已渲染卡片与滚动位置，不显示阻塞式加载提示，不抢焦点。
- 封面缓存键由资产修订驱动（`coverVersion` + `thumbnail_ready` + 状态），不在每次 render 拼时间戳；图片首次缺失、缓存过期、后台完成或手动重试后无需整页刷新即可恢复；重试次数耗尽后显示准确终态与可用操作。
- 操作按论文管理 pending：同一论文重复点击被忽略，不同卡片可并发；**只有论文已入库且 PDF 可读时才标记已读并进入阅读器**，失败不提前标记；错误就地显示在卡片上，详情与重试入口都可用。
- 主操作语义：已有可读 PDF「打开阅读／加入并阅读」；尚在获取时显示状态且不谎称可打开；失败时「重试获取 PDF」；仅封面失败时「重新生成封面」。

## C. 与首页一致的明亮卡片

- 卡片统一为：封面容器 → 分类/状态标签 → 标题（两行）→ 作者（一行）→ 摘要（固定三行）→ 底部动作；动作 `margin-top: auto` 底部对齐。
- 真实图、加载态、失败态、空态共用**同一固定高度**封面容器（桌面 210px、≤640px 190px，`object-fit: cover; object-position: top` 以首页顶部为主体），图片出现不推挤正文。
- 字阶回到规范（标题 16/15px、正文与按钮 ≥13px），不再用 10–11px 换密度；列宽优先保证阅读（`minmax(290px, 1fr)`），窄屏一列且全页无横向溢出。
- 分类标签与抓取分区区分显示，不改写上游元数据。

## D. 调度与维护可解释

- 每个 owner 的发现工作只允许**一个活动轮次**：调度触发、手动"获取论文"共用同一守卫；重复请求跳过或明确返回 `round_already_running`（409），不再悄悄再发一轮模型调用。
- 排队执行前、等待间隔结束后以及**每个日期边界**都重新检查 `enabled` 与暂停状态：停用或暂停后不启动已失效的排队轮次；已经开始的单篇工作安全收尾、结果保留，不杀 Web/Worker。
- 新增最小维护能力：`POST /api/daily-arxiv/scheduler/pause` 与 `/resume`；`scheduler/status` 返回可靠状态机（`stopped` / `disabled` / `idle` / `round_active` / `paused` / `paused_waiting`）与轮次开始/结束/结果、跳过原因计数，UI 不再靠日志关键词判断。
- UTC+8 业务日、订阅、配额、保留期与检查间隔保持不变；"没有新论文"不是失败。
