# iPaper 1.13.3 — 已发布镜像的笔记边界补强（V1/V2 复核追加）

候选发布记录；Registry 摘要及最终门禁结果在发布验收后填写，不能视为已经部署。

## 为什么再发一个补丁

1.13.2 修好了 1.13.1 复核的 V1–V6（隔离套件与复核复现全部通过），但用**已发布镜像的静态前端**做真实镜像验收时，又暴露两处只影响真实时序的边界，属于同一主题的收尾：

1. **保存期间切换面板后再重挂载**：较早请求在面板卸载后成功返回时，草稿表里的基准修订没有随之推进，重挂载后继续保存会拿旧基准 → 制造一次假冲突。现在成功响应即使组件已卸载，也会把草稿表的基准修订更新为服务器确认的新修订（草稿文本保持最新）。
2. **决定之后仍有在途定时保存**：一次失败保存排定的自动重试可能在冲突已被决定、编辑器已换成服务器正文之后触发，用旧基准把服务器正文当草稿再提交一次 → 制造重复冲突。现在任何决定（以及成功保存）都会取消待发的重试，重试回调也会跳过"草稿与已确认正文相同"的情况。

两处都只影响真实浏览器时序，不在隔离静态断言里；修复后镜像验收的 V1/V2/V3/V5 场景在**本补丁的确切产物**上通过。

## 与前两个补丁的关系

- 1.13.1 → 1.13.2：修复复核 V1–V6（草稿生命周期、冲突状态机、写入限流、严格修订比较、摘录回访、发布边界）。
- 1.13.2 → 1.13.3（本补丁）：修复真实镜像验收追加发现的上述两处时序边界，并把镜像验收脚本纳入仓库（`frontend/production-notes-v132.spec.ts` + `playwright.production-v132.config.ts`）。
