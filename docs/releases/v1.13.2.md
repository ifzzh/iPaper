# iPaper 1.13.2 — 笔记可靠性与写入限流补丁（V1–V6）

候选发布记录；Registry 摘要及最终门禁结果在发布验收后填写，不能视为已经部署。

## 为什么发补丁

Web 1.13.1 的独立复核（`.devnotes/ipaper-1.13.1-review.md`）确认笔记可靠性仍未完整通过：较早请求的结果会删除或覆盖较新的恢复草稿（V1）、冲突决定没有完整应用到编辑器且失败重试产生无操作入口（V2）、笔记保存落在通用 60 次/小时限流（V3）、显式 `null` 可绕过冲突决定的修订比较（V4）、笔记中的摘录没有回访入口（V5），以及发布差异不只有内容类型标签（V6）。本轮逐项修复，并把复核的 2 个后端 + 5 个浏览器复现纳入常驻回归；**没有放宽任何修订校验**。

## V1 保存版本与草稿生命周期一起修复

- 成功、失败、冲突与"未知结果"四条路径都只把**最新**文本写入草稿表（`draftRef`），不再用请求快照覆盖更新的输入：较早请求成功时若已有更新输入，草稿不被删除而是以新修订为基准继续保存；较早请求失败也不会把 A 写回覆盖 B。
- 草稿按 `owner + paper` 隔离并跨问答/批注/笔记切换、侧栏收起、原文/译文切换与论文切换存续；重新挂载时自动恢复**并继续保存**（失败草稿同样带上有界重试），组件卸载不再等于草稿失效。
- 未知结果先 GET 对账：服务器已有**最新**文本→确认已保存；只有请求快照已提交→仍保留更新的草稿并继续保存；服务器已前进→进入真实冲突。每请求带论文/账号纪元，迟到与重复响应不能改写新论文或新账号的编辑器。

## V2 冲突是一个完整、可操作的状态机

- 409（服务端冲突记录）与重试对账发现的远端变更（**本地冲突**）进入同一状态：并排展示服务器版本与我的草稿，给出「保留服务器版本 / 保留我的草稿」，**不再出现只有文案没有按钮**。
- 保留服务器版本：编辑器、基准修订、草稿与状态一起同步到该决定返回的版本。
- 保留我的草稿：提交用户**当前确认**的正文（随决定发送 `markdown`），不是冲突时的旧快照；被替换的服务器版本另存副本。
- 决定期间暂停防抖与 blur 自动提交，决定请求防重复；未作决定前不推进本地基准，普通保存无法绕过冲突；决定后又有第三次写入时拒绝旧决定并展示新冲突。
- 面板级冲突提示与编辑器内按钮等价（面板入口携带编辑器当前正文），笔记与批注入口共享状态。

## V3 笔记写入的独立 owner 级限流与退避

- 新增 `note_writes` 桶（**120 次 / 60 秒**，owner 级），覆盖笔记 PUT、批注增删改、摘录插入、回答复制与冲突决定；**不再消耗**通用 `mutation`（60 次/小时）。
- 容量依据：1.2 秒防抖 + blur 合并下，连续输入最坏约每分钟数十次保存；复核的"每十秒保存一次、连续十分钟"（61 次）全部成功；远超人类速度的爆发（每秒 2.5 次）仍在窗口内被拒。
- 前端读取并遵循 `Retry-After`：显示还需等待多久、保留最新草稿、等待期间继续输入并在到期后保存**最新**文本；手动重试同样遵循等待；畸形/缺失头使用 ≤60 秒有界后备，固定 3/8/20 秒退避不再轰击长窗口。其他敏感入口阈值不变。

## V4 冲突决定的修订比较严格化

- `revision` 缺失或类型错误 → 400；`null` 只与**实际不存在**的当前版本匹配，不再是通配符；空字符串、旧字符串与错误字符串一律 409，并保留未见正文的副本。
- 覆盖矩阵（缺失 / `null` / `""` / 错误类型 / 旧字符串 / 正确字符串）进入常驻测试；旧删除修订的撤销仍返回 409。

## V5 从笔记里的摘录回到来源

- 笔记「来源」列表的摘录带上 `annotationId` 与「回到来源」入口，复用批注自身的受控来源定位（原文 PDF / 版式译文 / 结构原文 / 结构译文各自的页、块与译文修订），不新建另一套导航。
- 新增单条批注读取接口用于该入口；批注被删除时保留摘录并明确提示"来源批注已被删除，定位仅供参考"，来源版本失效时按既有规则降级，不按当前相似文本伪造定位。已保存 AI 回答的来源与导出保持不变。

## V6 发布边界

`ac82ea1..9f83967` 之后的运行行为改动（409 后先重取当前版本再展示冲突、组件纪元校验、内容类型标注）与本轮 V1–V5 一并纳入 1.13.2 的发布矩阵；验收与复核使用**本补丁确切的前端产物与配套后端**以及发布后的固定摘要容器，不用"最新源码测试通过"代替"已发布镜像通过"。

## 限制与回退

- 不含跨论文笔记工作区、Agent、RAG、图谱与带批注 PDF 导出。
- 结构内容的摘录回访仍以存下的范围与完整摘录校验为准，无法匹配时只显示块级来源与说明。
- 回退基线 **Web 1.13.1 ＋ Workers 1.2.0**：回退不会丢失已保存的笔记/冲突/来源记录（schema 只有兼容增量），但会重新暴露 1.13.1 的 V1–V5 缺陷（草稿覆盖、冲突无操作入口、限流过严、null 绕过、摘录无入口）。
