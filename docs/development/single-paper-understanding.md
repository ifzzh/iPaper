# 单篇概览、深度解读与问答

1.3.0 的实现范围是同一论文的作者摘要、AI 概览、长篇解读、局部/整篇问答、可信来源和分析导出。它不新增 Agent、跨论文检索、笔记或批注。发布与正式验收状态见对应 Release；源码实现不等于真实供应商验收。

## 内容与版本

`ipaper/processing/understanding_store.py` 优先读取匹配当前原始 PDF SHA-256、规范化版本兼容的合并结构解析。完整性由分段清单、完成状态及全局页码覆盖核实；内部单段和译文完成比例不代表全文。AutoSci 的 237 个原文块可用于分析，六块译文不会限制输入。

没有完整结构时使用已有部分解析或旧 Markdown，并要求用户确认实际覆盖范围。旧 Markdown 用文字哈希记录快照，不补造 PDF 文档、块或坐标。没有正文时只展示元数据和旧分析，创建解析须明确操作；正式镜像不提供 MinerU CLI。打开页面、切换结果和命中缓存都不调用模型。

新增 `understanding_artifacts`、`understanding_heads`、`understanding_evidence`、`understanding_chat_turns`，不重写论文/聊天/任务表。不可变正文、图片、分段检查点、分析及导出均在原 owner 隔离 `.artifacts/<UUID>` 下，事务提交前校验、fsync 文件，提交可见指针失败清理本次新目录。原文件及 BabelDOC 产物不移动。

快照绑定源指纹、解析与正文版本、阅读顺序、覆盖范围。概览与长解读分别保存提示词、语言、模型、凭据修订和结果历史；沿用 interpret 凭据，GET 不返回密钥。明确更新与缓存读取区分，完成新版本后才交换当前指针，迟到结果不能覆盖另一更新。源 PDF 变化后旧结果可读可导出，来源只能回看保存的摘录。

## 生成与问答预算

概览六部分为背景/问题、方法、实验、发现、结论/局限、继续阅读重点。长解读保留原 PaperPilot 图文风格，解释关键公式、表格、实验和消融。模型只接收原文、表格文字、图注及已核实的图片引用，未发送图像像素。

生成按阅读顺序分段处理全部纳入的原文；概览再汇总证据笔记，长解读组织连续分段。定位几何不进入模型输入。每段及汇总成功后保存检查点；部分失败不冒充全文完成。生成前显示请求和 token 保守上限，执行前逐请求预留预算。沿用 processing 全局并发 2、每用户一个活动任务、队列 20，以及**本类型自己的**额度上限：概览/深度解读/分析导出仍是 200 请求 / 50 万输入 / 25 万输出 token / 两小时——2026-09-20 起整篇结构化翻译的默认与上限提高了（见 [双轨翻译](dual-translation.md)），但**不适用于本类型的概览与解读**，也不能通过 API 调大。单请求 120 秒、SDK 重试 0；仅明确 429 拒绝允许一次有限重试，结果未知不自动重发。取消停止后续领取，正在执行的有界请求仍可能产生费用。

概览提示词版本 2 将中间证据笔记与最终六区概览分开：分段请求上限 2048 token，只提取短事实和少量逐字来源；校验后的笔记最多 4000 bytes，以最多五份逐层汇总，最终概览上限 4096 token。AutoSci 的五个正文分段因此需要五次提取和一次汇总，预检输出上限 14336 token。长解读仍按正文分段各自生成详细内容，不套用简短笔记格式。模型返回长度截断时保留结束原因和用量，不把不完整 JSON 当可读分析。

整篇问答对短文使用全部原文；长文对全文分段索引评分，向一次受限辅助选择请求提供匹配片段和全篇分布样本，再核实 ID、对全部原文重新评分并读取有界证据。最多一次选择和一次回答；不新建向量库。界面区分检索范围、实际使用单元和图片输入能力，不宣称模型读过未发送正文。局部模式没有有效选区/当前段落时拒绝，不隐式升级成全文。

问答请求 UUID 与服务端事务防止重复用户消息和重复付费请求。同用户已有活动问答时拒绝第二个；每回合的准备、流式、保存或中断状态独立于客户端是否继续读取。公共流仍为首行会话 JSON、后续原始文本；最终以持久历史为准，失败不自动重发。

## 来源、渲染和导出

分析来源须有本次原文中逐字匹配的证据摘录，问答链接须命中服务端提供的来源映射。任意模型 URL、路径、未知编号均不会变成可信来源。来源可回当前 PDF 页/区域，或返回旧 Markdown 摘录。模型引用编号通过验证只证明关联到上下文；仍需人工核对事实是否由证据支持。

统一页面使用安全 Markdown、DOMPurify 和自托管 KaTeX MathML；不接受模型 HTML、外部图片或任意磁盘路径。分析图片用 owner 校验的摘要地址读取；旧原始 PDF 缺失也不阻止授权历史分析图片读取。

导出是零模型请求的持久有界任务，每包上限 32 MiB。Markdown 保留层级、公式、表格及证据摘录；图片 ZIP 只复制已核实引用，用相对路径，附离线说明及缺图声明。未批准图片语法按文本保留，不自动下载外部资源。浏览器打印使用专用样式并等待图片/字体，释放视口高度约束、重复表头、处理宽表与公式；如实称为浏览器打印/另存为 PDF。

## 接口与兼容

- `GET /api/paper/<id>/content`：正文版本、覆盖和缺少内容。
- `GET /api/paper/<id>/understanding[/<result>]`：独立结果、历史及旧 `legacy` 解读。
- 原 processing 预检/任务/日志/取消/继续接口增加 `overview`、`interpretation`、`analysis_export`。
- `GET/PUT /api/settings/paper-understanding`：两个提示词和语言，引用 interpret。
- `GET/PUT /api/paper/<id>/understanding-position`：两类分析位置及共享会话选择；PDF/结构位置保持原接口。
- 聊天增加可选 `scope`、`content_version`、`request_id`、`allow_partial`；旧无来源请求映射全文，未知完整性仍须确认。
- `GET /api/paper/chat/turns/<id>`：回合终态与实际范围。
- 原分析启动接口复用新长解读；读取兼容新结果及历史 `result.md`。

写入要求 CSRF、会话、owner、大小和版本校验；文件和下载私有 no-store。解析及两种翻译不改变既有协议或 Worker 职责。

## 备份和回退

`backup_processing.py` 的一致性快照同时包含理解产物及引用图片，不仅备份数据库。发布前仍用受限完整备份及持久 `rollback_release.py`；回退 1.2.0 保留新增表与不可变文件，旧版不显示新分析但不删除它们。继续使用当前数据库，旧版期间新增论文/聊天保留，再升级重新读取新结果。不得拿旧数据库快照覆盖升级后的用户数据。


证据校验版本 2 允许明确省略号引用的受限恢复：片段必须在指定单元内唯一、逐字且顺序一致，保存实际原文连续摘录。不存在、歧义、倒序、过短或过长跨度均拒绝，不将模型编号或语义相似视为证据。结果提示词版本仍为 2；两者均进入有效配置与缓存判断。
