# 双翻译与来源定位（1.2.0）

本文件描述 1.2.0 源码契约；正式可用版本、真实供应商验收与镜像摘要以 Release 为准。三服务职责保持：Web 调度、云通信与模型请求；Document Worker 分段/归档/规范化；Translation Worker 执行 BabelDOC。没有第四个常驻服务。

## 阅读和生成

阅读内容分为原始 PDF、版式译文、结构阅读。结构阅读再选择原文、译文或逐块双语。版式结果分别登记纯译文和双语 PDF；旧 `translated`、`chinese/file` 和阅读位置继续兼容。已有内容切换仅产生读取和位置保存，不自动解析或翻译。

统一生成弹窗显示方式、语言、页码范围、模型及处理预算。MinerU 是解析器，结构化译文由独立模型配置生成。ifzzh 的配置仅在尚无独立配置时由服务端从 BabelDOC 解密、重新加密初始化；不会覆盖已有独立设置，也不把密钥返回浏览器。其他用户可主动复制配置。

文档预检在 Worker 中核对几何与分段；每段不超过 200 页及当前文件大小限制，整体仍受 2,000 页、100 MiB 输入限制。全局最多两次预检、每用户一次；预检不调用云服务。结构块、图片、PDF 页面均按需加载。正文和表格中的公式使用不信任输入的 MathML 渲染，公式/数字在翻译前保护；无法解析的公式显示原始表达式。

## 增量数据与原子产物

新增 `processing_*` 表保存文档版本、结果、块索引、成功译文版本、任务、事件、请求尝试、来源、聊天引用、独立配置及阅读位置。旧论文、聊天表不重写；既有翻译任务增加默认 `dual` 的输出模式。旧运行版本忽略新增表，不向旧凭据用途表加入新用途。

文件在 `<papers>/.users/<owner UUID>/.artifacts/<server UUID>/` 保存。SQLite 只索引文件、哈希和状态。临时写入、校验、原子重命名后事务更新可见版本；单块失败不清空旧译文，晚到生成不能覆盖新版本。不同账号不共享缓存。缓存匹配源文件 SHA-256、解析版本、原文哈希、目标语言、模型地址/名称、配置修订和提示版本。

历史 BabelDOC 文件首先按现有位置登记，缺少生成证据时显示历史配置未知；明确重新翻译前冻结旧别名，成功新输出保存独立版本。已验证任务保存原始 SHA、输出模式、模型名称/地址等非敏感快照。论文分类改动不移动不可变产物。源文件变化令结构来源过期；旧内容仍可读，但不能高亮到替换后的 PDF。版式 PDF 使用自己的指纹和位置，不推断原译文坐标对应。

## MinerU 与坐标

旧分析链路的 Markdown 清理行为保持。新 `mineru_structure` 任务独立保留经验证的 content list、layout、Markdown、引用图片和清单；不在 Web 解压 ZIP。原包的路径、链接、类型、总量、压缩比以及单个顶层 UUID origin PDF 忽略规则继续执行。新任务 JSON 单文件 32 MiB、总量 128 MiB，深度 32、节点 100 万、字符串 2 MiB、块数 10 万，旧任务不扩大上限。

已验证区域路径限定 MinerU 3.4.4/hybrid 的 content-list 千分坐标和匹配的无旋转、无裁剪、UserUnit=1 页面。保存原解析坐标/约定和 PDF MediaBox、CropBox、UserUnit、旋转及变换；最终区域在 PDF 默认用户空间，浏览器用 PDF.js viewport 转为显示坐标。未知 schema 或变换降为页级；页码也未知时不提供 PDF 跳转。旋转页可阅读，不声称通用旋转 bbox 已验证。

分段清单在任何云任务前生成并验证，合并按原始页序映射。跨段块不猜测拼成段落。重新解析创建新版本；旧引用绑定旧块和原文件指纹。

## 任务和费用边界

默认全局两个结构模型请求、每用户一个活动任务、待执行队列 20 个。一次模型请求最多 8 个文本子单元；过长段落/表格拆分后逐单元保存检查点。

**额度按任务类型区分。** 整篇结构化翻译（`translate`、`parse_translate`、`retranslate`）默认 **500 次模型请求 / 100 万输入预留 / 50 万输出预留 / 4 小时**；2026-09-20 之前是 200 / 50 万 / 25 万 / 2 小时，正常整篇论文会被挡住。部署上限为 **2,000 / 500 万 / 200 万 / 12 小时**，可由 `IPAPER_TRANSLATION_MAX_REQUESTS`、`IPAPER_TRANSLATION_MAX_INPUT_TOKENS`、`IPAPER_TRANSLATION_MAX_OUTPUT_TOKENS`、`IPAPER_TRANSLATION_MAX_SECONDS` 覆盖（必须是正整数，配置非法时启动直接失败）。

这四个变量配置的是**最大值，不是默认值**。校验作用于**最终合成额度**：默认、空预算、部分字段与显式预算四条路径都会逐维度比对上限，任何一条都不允许超过。当管理员把上限降到内置默认值以下时，有效默认值即被压到该上限（启动日志会说明，预览返回 `defaultCappedByCeiling`），因此不会出现“上限 100、默认 500 仍然准入”的情况；显式请求超过上限时返回 `invalid_budget` 并指出具体维度。概览、深度解读、分析导出、划词翻译与纯解析（MinerU）**保持原上限不变**，API 也无法把它们调大。

界面在“调整本次额度”展开区提交请求、输入、输出与小时数；默认值、上限都由服务端返回，页面不复制常量。估算与提交使用同一份已确认额度；超出时明确指出是哪一项（所需与当前额度），并提供一键调整。估算给出**基础请求**、**允许的 429 重试余量**（每次基础请求最多一次）与两者之和，避免把重试上限误称为“最多请求数”。

估算以 UTF-8 长度作保守界限，是预扣而非计费用量：任务详情分别显示“已预留”（保守预扣）与“供应商实际用量”，且**输入与输出分别判定完整性**——只有两个维度都拿到合法供应商数据才显示“完整”，单项缺失显示未知/部分统计并给出缺失次数，未知用量不退额、也不推断未计费。

超出提示里的“使用所需额度”填入的是**准入所需的保守预留（基础请求）**；如需覆盖每次请求最多一次的 429 重试，另有用户主动选择的“含 429 重试余量”选项，它同时提高**请求、输入与输出**三个维度（不是只把请求数翻倍）；超过部署上限时明确拒绝并提示手动填写或调整上限。解析前无法可靠估算块数；解析后先核对范围，超预算时**保留解析结果**并展示新的范围与额度调整入口，等用户明确继续。

**旧任务续跑。** 已保存任务沿用原 `budget_json`，不在启动时批量改库。对因额度/时限停止（`partial`/`interrupted`/`failed`/`cancelled`）的整篇翻译，任务详情提供“调整额度并继续未完成部分”：`POST /api/processing/jobs/<id>/resume-plan` 只读返回已用量、剩余估算（已应用单元检查点；单块重译使用与执行侧相同的 `force` 语义，不把旧成功译文当作本次重译已完成）与所需额度；`POST …/resume` 携带 `budget` 时校验部署上限且**不得低于已用量**，新额度是**整个任务的累计总额**——已完成的块与子单元继续复用，已用请求/token/时间不清零。重复点击不会重复排队（同一 owner 只允许一个活动处理任务）。

**时间维度是独立的一维。** 剩余执行时长无法预先估算，但“已经耗尽”是确定事实：有计划中工作时，若累计时间已用满，续跑计划判定**不足**（`time.exhausted`、`overage.seconds.required = 已用+1`，是下限而非估计），界面提示“累计执行时间已用完”并允许**只延长小时数**就继续；服务端同样拒绝在时间耗尽时入队（`budget_time_exhausted`），不会入队后立刻再次超时。反之，若检查点显示已无待发请求，续跑只做发布，不因时间耗尽失败（状态检查与时间检查分离）。

模型凭据仅经 stdin 管道进入一次性传输子进程；最多两进程，父进程在 120 秒墙钟截止时终止进程组。它不是新常驻服务。SDK 自动重试关闭；仅明确限流拒绝最多再试一次。超时、断线和结果未知不自动重发。幂等任务创建返回原任务，取消停止新请求但不声称供应商已取消或未计费。重启将未完成任务标为中断，用户明确继续；已知 MinerU batch 只查询，未知创建不重提。已保存翻译子单元从恢复估算中扣除。

每结果默认 1 GiB，每账号 10 GiB；用 `IPAPER_STRUCTURE_RESULT_MAX_BYTES`、`IPAPER_STRUCTURE_OWNER_MAX_BYTES` 调整。终态临时检查点也计入占用，保留 7 天；详细事件 30 天，终态摘要保留。不可变结果和被引用版本不自动删除。原始 ZIP 是短期检查点，不暴露为浏览器资源。

## 可信问答来源

选区由服务端校验 owner、文档/结果/译文版本和 UTF-16 文字范围，生成来源 UUID。PDF 文字通过 Worker 对该页核实，当前仅给页级来源。结构问答没有显式选区时，在确认发送后使用当前可见块及相邻块；最多 8 个来源、12,000 字符，不建立检索索引或自动解析全文。

仅将实际进入上下文的来源编号交给模型。回答中的 `[S1]` 只有命中本次映射才产生可信按钮；任意路径、URL、块 ID 和编造编号无效。来源映射与助手历史在同一事务保存；仍使用首行会话 JSON＋后续原始文本的现有流协议。流结束从持久历史核对；未保存显示提示，不自动重发。旧聊天不补造引用。
