# 阅读与界面性能

## PDF 与封面

正文与封面分别调度。用户明确打开的 PDF：已知文件大小不超过 12 MiB 时使用单请求流式读取，减少读取交叉引用表造成的串行往返；大文件或大小未知时使用 512 KiB Range，关闭流式与自动预取。封面继续使用 256 KiB Range，只为可见卡片串行渲染真实首页，不为列表下载整篇。正文优先渲染恢复位置所在页，首个可读页面出现后才放开相邻页；初始缩放从真实可用宽度计算，避免先按错误比例重复渲染。

阅读器与封面复用解析 Worker。正文离开后允许在当前页面会话内短时复用已解析文档：最多两个空闲文档、文件大小之和不超过 24 MiB、每份不超过 400 页、两分钟到期。此处是准入文件大小预算，**不是实际堆内存上限**。离开十秒后清理重型页面缓存；再次读取仍需渲染。超过边界立即销毁。原文、历史译文和受控文档接口均返回内容 SHA-256 的强 ETag，同大小/原时间戳替换也不能复用旧版本。每次打开（含命中复用）均通过已认证、no-store 的 HEAD 核对 ETag；内容改变或鉴权失败拒绝复用，新读取以 If-Match 绑定对应版本。退出、会话失效或账号切换会清空文档/像素缓存和 Worker；销毁后清理 PDF.js 文字测量 canvas。文档与凭据均不写磁盘缓存或 localStorage。

正文在视口前后 250px 开始渲染，离开 1600px 保留区后释放 canvas 与文字层；缩略图使用更小窗口。缩放、旋转和批注继续计算真实坐标。阅读位置与文件指纹核对后恢复，读取失败不会覆盖旧位置。译文先确定结果版本再打开文件，避免旧入口与当前文档各加载一次。

服务端对同一 owner 的稳定文件摘要合并并发扫描：缓存键包含 owner、路径、设备/inode、大小、纳秒 mtime/ctime 和 inotify 修改代数；每次重新打开文件、核验并排空通知。替换、原地编辑或通知队列溢出均使旧摘要失效。监听不可用时始终重新哈希，不靠 stat 猜测文件未变。摘要/监听各有 128 项边界；不缓存文件字节或持有打开的文件描述符。每个路由仍重新做租户鉴权和路径约束，私人 PDF/API 保持 private、no-store，Range 支持保留。

封面像素另有 12 MiB 内存边界；每次复用均以已认证 HEAD 校验对应 ETag。打开未变化的论文或卡片不会触发模型、MinerU、OCR 或翻译。

## 请求与数据库

`useResource` 合并同账号、同 URL、同时在飞的 GET；完成后立即移除，不缓存接口结果。每个订阅者独立取消，最后一个离开才中止请求；切换账号会清空并中止旧请求。主题侧栏复用文献库已读的主题目录。后台轮询仅在可见页面且上轮结束后执行。

分页列表批量读取概述、已采用元数据及标签，保留概述失效规则、人工修改和 owner 限定。Daily 临时记录在 SQL 层先排除，避免逐条解码它们的 JSON；最终仍通过同一入库判定。

## 静态资源

构建时生成公共 JS/CSS 等文件的 gzip 副本，仅公共 `/static/workbench/` 静态入口协商压缩；不压缩私人 API 或 PDF。响应带 `Vary: Accept-Encoding`，不同编码使用各自 ETag。内容哈希命名的 JS/CSS 可长期缓存；入口 HTML 保持 `no-store`，更新后引用新哈希。

## 验证口径

性能记录区分首次与再次访问、PDF 原文与译文、网络请求数和实际文字层就绪时间。单次本机计时不是外网速度保证。功能门禁同时覆盖 300 页搜索、阅读位置、缩放旋转、批注与笔记。禁止通过跳过鉴权、减掉文字层或无限保留所有页面来获得更短计时。

## 运行依赖

本轮安全依赖升级后，源码环境支持 Python 3.11–3.13，正式 Docker 使用 Python 3.12。Web、Document Worker 与 Translation Worker 的锁文件分别审计；BabelDOC/MinerU 的业务版本未因性能优化变更。

发布构建对 Ubuntu 执行系统安全更新，并使用 `--pull --build-arg APT_REFRESH=YYYY-MM-DD` 刷新基础层与 apt 缓存。test 阶段位于最终镜像之后，独立执行完整门禁；构建三个运行目标不会因 Docker 旧构建器按顺序遍历而重复执行整个测试阶段。
