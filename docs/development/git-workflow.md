# Git 分支与发布流程

生效日期：2026-09-16。用户已确定采用 `main`、`dev` 两个远程长期分支；本地可以保留任务分支。本文记录生效约定，历史远程分支清理及 CI 配置收敛须按实际执行结果记录，不能视为已经完成。

## 分支职责

| 分支或引用 | 职责 |
| --- | --- |
| 远程 `dev` | 日常开发的统一集成入口；接收本地已经整合、验证的改动 |
| 远程 `main` | 稳定发布线；在发布或稳定版本维护时接收已验证的 `dev` 提交 |
| 本地任务分支 | 承载具体开发工作，可在现有分支提交；新任务分支默认使用 `codex/` 前缀 |
| `v*` tag | 固定每次发布的源码提交，已发布 tag 不改写 |

远程只保留 `main` 和 `dev`，默认分支继续为 `main`。本地任务分支不要求推到远程，也不要求本地分支数量与远程一致。此前 `main`、`dev`、`personal-paper-reading` 三分支同步属于历史流程，不再沿用。

## 日常开发与集成

```text
本地任意任务分支提交 → 合入本地 dev → 验证合并结果 → 推送 origin/dev
```

1. 开始工作前读取分支、工作树及远程最新状态。新任务优先从已同步的 `dev` 创建本地任务分支；已有工作在原分支继续，不因分支名称不同重做或丢弃提交。
2. 在当前工作分支提交本次任务的改动，只显式暂存相关文件。保留用户及其他任务的未提交修改，不能使用整体重置、清理或随意打包暂存来换分支。
3. 集成前 fetch 远程，先让本地 `dev` 纳入 `origin/dev` 的最新提交，再合入本地任务分支。可快进时优先快进；不能快进时先审查分叉、解决冲突并验证最终合并结果，不能强推或丢弃一侧提交。
4. 核对实际将进入 `dev` 的全部提交，确保没有顺带合入其他未完成工作；运行受影响检查。通过后用明确目标推送：`git push origin dev:dev`。
5. 从远程重新读取 `dev` 提交，确认推送成功；本地 `dev` 跟踪 `origin/dev`，本地 `main` 跟踪 `origin/main`。不能把更新远程分支当作本地同名分支已经同步。

如果当前就在本地 `dev` 开发，无需另建分支或执行自合并；纳入远程最新提交、完成检查后直接推送 `dev:dev` 即可。

当前工作区有其他任务的改动或占用时，应使用独立 worktree 完成集成，或等待该工作区可以安全切换；不得擅自改变执行中任务的分支。一个分支不能同时在两个 worktree 中检出，先核对现有占用。任务分支合入 `dev` 后，后续工作要纳入新的集成结果，避免一直从陈旧分支继续叠加。

推送日常开发只更新 `dev`，不顺带更新 `main`、创建 Release、移动 `latest` 或部署服务。禁止用 `--all`、`--mirror` 或批量 refspec 将本地任务分支全部发布到远程。这里的分支流程不替代具体任务已经明确获得的推送与发布授权。

## 正式发布与维护

```text
已验证的 dev 发布候选提交 → 本地 main → origin/main → 固定 tag／Release
```

发布时确定具体候选提交，而不是默认将不断变化的 `dev` 最新内容全部发布。完成相应测试和发布门禁后，将候选提交晋升到本地 `main`，再明确推送 `git push origin main:main`。优先让 `main` 快进到同一个已验证提交；若两个长期分支出现分叉，先在 `dev` 解决并重新验证，不能产生未经验证的合并结果后直接发布。

发布 tag、镜像 revision 与归档构建必须对应确定的发布源码提交。GitHub Release、镜像、组件矩阵、正式部署、远端摘要和 `latest` 继续遵守既有发布规则；更新分支本身不代表正式环境已升级。

发布后的镜像摘要、验收文档和配置示例收尾也先进入本地及远程 `dev`，复核后再同步到 `main`。尽量在开启下一阶段功能前完成收尾；如果 `dev` 已有未发布功能，不能借同步文档把这些功能一起推进 `main`。后续记录不覆盖已有发布 tag 或版本镜像。

稳定版本修复同样先集成到 `dev`，再按明确发布范围晋升 `main`；不恢复三分支同步，也不从任意本地任务分支绕过 `dev` 直接更新远程 `main`。

## 分支收尾与历史分支收敛

每轮集成结束后检查本地分支，不把永久保留任务分支当作版本备份。只有同时满足以下条件才清理任务分支：

- 分支提交已经完整包含于远程 `dev` 或 `main`，没有仅存本地的独有提交。
- 分支不再承担进行中的工作，也没有 worktree 或执行任务占用。
- 所需后续修改已被接续，相关用户改动没有遗漏；不使用强制删除绕过未合并检查。

远程历史分支先核实所有独有提交及依赖，再收敛到 `main`、`dev`。旧 `personal-paper-reading` 和已完成的远程任务分支不再承接新提交；清理不能删除历史 tag、Release 或镜像。Git 的 fetch/prune 只清理失效的远程跟踪引用，不会自动删除本地任务分支。

CI 的长期分支触发范围同步收敛到 `main`、`dev`，保留需要的 PR 检查；不再因历史第三分支重复运行。是否已完成 CI 修改、远程清理和保护设置，以实际仓库状态为准，不因本文生效而提前标记完成。
